# Bi-objective-robust-TSPTW
A heuristic algorithm for solving the data-driven robust TSPTW under travel time uncertainty.

This repository contains the data and source code associated with the manuscript:

**"Balancing cost and robustness in the traveling salesman problem with time windows under travel time uncertainty: A bi-objective robust optimization approach."**

The repository provides:

- the original TSPTW benchmark instances,
- the in-sample and out-of-sample travel time scenarios,
- the generated DRTSPTW instances,
- the C++ source code used to compute the experimental results,
- the python script to plot the figures
- and the raw output files used to produce the tables and figures in the manuscript.

Note: No pre-compiled executable is included. The C++ source code needs to be compiled locally.

## Data

The repository includes the following data sets.

### Original TSPTW benchmark instances

These are the original benchmark instances used as the basis for the experiments. There are two N60 instances n60w120.001 and n60w200.001, and one N12 instance rbg010asep. The instances are in the following format: name, number of nodes, cost matrix, travel time matrix, and time window.

### In-sample scenarios

These travel time scenarios are generated using a two-point distribution or a uniform distribution. There are different sample sizes considered for N12 set, but only one sample size for N60 set. These scenarios are used to construct the robust instances that are later be solved in the BRTSPTW.

### Out-of-sample scenarios

These scenarios are reserved for evaluation only and are not used during model construction.

### Generated DRTSPTW instances

These robust instances are generated from the original benchmark instances and the associated scenario sets. The surrogate BRTSPTWs are solved on these instances.

## Source code

The `code-1_main_algo/` directory contains the C++ implementation used to solve the BRTSPTWs to obtain the candidate tours.

The code includes:
- instance reading and parsing,
- runner for main algorithms (MDLS and MBBM),
- and output formatting.

The `code-2_evaluation/` directory contains the C++ implementation used in the computational experiments.

The code includes:
- generate the performance indicators to evaluate the performance of MDLS and MBBM,
- generate the delay budget sub-intervals based on the BRTSPTW(B) solutions,
- evaluate the candidate tours on the original scenarios and compute the cost-infeasibility tradeoff curves (with different metrics), and
- evaluate the candidate tours on the original scenarios and compute the relevant infeasibility measures for selecting a single DRTSPTW solution

The `src_plots/` directory contains the Python script used to generate the figures for the evaluation.

The code includes:
- generate the performance comparison table for MDLS and MBBM,
- generate the cost-infeasibility tradeoff curves with different metrics, and
- generate the table for evaluating the infeasibility measures under DRTSPTW criteria.

## Outputs

The `data_output/` directory contains output files generated by the experiments, including:

- BRTSPTW solution files (candidate tours for the DRTSPTW),
- raw data used for evaluation in different computational experiments

The `visualization/` directory contains raw tables and figures generated by the Python scripts. They are used in the manuscript for visualization, including:

- raw data for the table to show the performance comparison of MDLS and MBBM,
- raw data used to plot the cost-infeasibility tradeoffs and the resulting figures, and
- raw tada for the table to show the evaluation of the selected solution under DRTSPTW criteria.

## Tables

The repository includes the **raw numerical output files** used to generate the tables in the manuscript.

## Figures

## Reproducing the experiments

To reproduce the reported computational results:

1. Compile the C++ source code using a C++17-compatible compiler.
4. Run the optimization code on the relevant instances. Note: the objectives (i.e., cost vs. worst-case delay budget size, or cost vs. robust slack) and the method (MDLS or MBBM) need to be manually set in the configuration. The in- and output file paths may also need to be adjusted.
5. Run the evaluation code based on need. Note: The in- and output file paths may need to be adjusted. For different evaluations, the corresponding code needs to be used.
6. Run the corresponding Python script to get the table or figure. Note: The in- and output file paths may need to be adjusted.
